# Native Canvas interaction references

2026-11-09 · Issue [#17](https://github.com/avacadorun-dev/writer-craft/issues/17) · [F-47](../design/USER_FEEDBACK.md#f-47--reject-improvised-connection-ux-evaluate-native-react-flow-behavior)

## Decision and evidence boundary

Develop a maintained native reference-port in the separate **CraftCanvas** repository. React Flow supplies the observable interaction reference; `egui-xyflow` and `egui-snarl` supply useful implementation references. This selects neither a drop-in dependency nor a replacement canonical graph. Preserve the existing native architecture, `f64` world geometry, stable edge/node IDs, unknown JSON, guarded commands, history and embedded-input ownership. An application-wide egui upgrade is not justified by this comparison.

The subsequent user instruction broadens the objective: prepare standalone CraftCanvas for production with **full React Flow functional parity**, while delivering the engine primitives required by current WriterCraft first. The ordered library issues establish an exact WriterCraft-ready handoff before completing remaining standalone parity; full Studio Canvas acceptance remains separate. The first connection deliverable below is an increment toward that objective, not its boundary. CraftCanvas owns maintenance and delivery; progress must not wait for upstream fixes or releases.

The candidate findings below are **static source deductions**, checked against the downloaded versioned archives and source snapshots. No candidate was built or interactively exercised in these audits. The runtime finding is separate: the user rejected WriterCraft preview `68db76e`'s connection UX. Passing checks or better line geometry do not override that finding. Neither this report nor an upstream screenshot establishes native acceptance.

The egui-xyflow audit observed publication on **2026-05-06** and a later main compatibility commit on **2026-10-26**. A release gap and limited observed activity are delivery risks, not evidence of abandonment. No promise about upstream response time is assumed.

## First coherent deliverable and retained scope

| Source contract | Required native result |
|---|---|
| **B15 — connections and labels** | Drag from a visible handle to a valid target; drag either endpoint of an existing edge to reconnect. Show a temporary route, valid/invalid target feedback and discoverable hover/selected handles. Cancel, invalid release, focus loss or stale authority retain the original edge and metadata. Keep distinct-side same-card loops and distinguish missing imported side from an explicit side. Direct path selection, visible labels and direct label editing belong to the same interaction; properties remain secondary. |
| **B11 — selection and geometry** | Hit testing respects painting order, clipping, camera transforms and active gestures. Handle/edge gestures must not accidentally move cards or create text. Mouse, keyboard, pan/zoom and embedded text/media controls have explicit input ownership. This increment does not complete B11's remaining resize/rotation obligations. |
| **B26 — authority and recovery** | Gestures create transient previews and guarded commands. Only successful durable acknowledgement advances canonical state; reconnect preserves edge identity. Exact-base Apply/Undo, failure/retry, raw drafts and recovery retain their existing contracts. No upstream mutable graph becomes a second authority. |

Qualify the engine revision before adoption, then review the actual compiled native interaction independently against F-47. Use targeted real regressions and coherent native workflows; scripted input is not OS/IME acceptance. These three rows identify the immediate work, **not all B01–B26**. [The complete Canvas inventory](../migration/CANVAS_PARITY_MATRIX.md), [role journeys](../design/ROLE_JOURNEYS.md) and full source/UX gates remain required. Standalone React Flow parity also needs its own complete capability inventory, including examples and native accessibility equivalents, before a production claim.

## Reuse and provenance

The inspected egui-xyflow and node_graph2 packages declare **MIT**; snarl and flow-editor declare **MIT OR Apache-2.0**. No upstream implementation is copied by this report. If source is ported, record repository, immutable revision, original files, chosen license, retained copyright/license notices and local modifications in CraftCanvas alongside the derived code. Keep behavioral inspiration distinct from copied implementation. Review provenance for each React Flow/core/example source separately; the public presence of a Pro example does not grant access to its implementation. New dependencies or broader architectural changes require their own recorded decision.
