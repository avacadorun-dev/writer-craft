## Relationship-model review

The four hypotheses describe different editing authority. They should not become four compulsory card categories or an implicit global synchronization system. A coherent minimum can retain independent notes, stable references and the existing guarded promotion operation while making their authority visible. Shared fields or pinned excerpts should be selected only where a scenario demonstrates their value. The proposed distinctions below are design conclusions to validate, not implementation approval.

Primary documentation was reopened on 2026-11-09. Final Draft documents shared beat content between its board and outline, a read-only script lane and a separate Send to Script copy operation. This supports separating one planning record's views from deliberate transfer into manuscript text; it does not establish universal two-way text sync. [Final Draft Outline Editor](https://kb.finaldraft.com/hc/en-us/articles/27613546469652-How-do-I-use-the-Outline-Editor).

Celtx documents author-triggered Sync Script, linked sequence headings and navigation, alongside independent sequences. This supports an explicit refresh boundary and understandable link state. Its documented storyboard reordering does not establish that free board geometry must rewrite script order. [Celtx Storyboard](https://support.celtx.com/hc/en-us/articles/216076228-Storyboard).

STARC's relationship map connects character identity to profile and relationship panels and permits separate character viewpoints. This supports stable character identity and directional relationship meaning; it does not justify automatically extracting profiles from manuscript names or changing dialogue when a profile changes. [STARC character relationships](https://old.starc.app/help/characters-relations).

Obsidian distinguishes independent text cards from note-file cards, explicit conversion, and heading/block narrowing. This supports visible identity/provenance and deliberate conversion. It does not make a matching title an identity or establish WriterCraft's deletion/Undo policy. [Obsidian Canvas](https://help.obsidian.md/plugins/canvas).

| Hypothesis | Design assessment | Required authority and failure contract |
|---|---|---|

All views acknowledge the same revision; concurrent edits become stale/conflict states. A board-layout Undo cannot undo canonical profile content. A private variant must remain independent or explicitly pinned. Entity fields and cross-view editing locations are still unselected. |

Current title/excerpt is a projection with clear target identity; editing opens the authoritative surface unless direct shared editing is explicitly selected. | Rename/move follows identity. A removed/detached target stays visibly unavailable and cannot silently attach to another equal name/quote. Retain origin board camera/selection and manuscript caret/scroll. Opening alone does not complete the connected authoring outcome. |
| H-LINK-3 revision-pinned snapshot | Useful candidate for a review decision, quotation or deliberately retained planning state. Avoid presenting it as the current manuscript/profile. It needs evidence of a historical-state task before adding another primary choice. | Show source identity/revision and outdated state. Refresh/replace is explicit, reviewable and guarded; no late update overwrites independent notes. Export/restore preserves pinned meaning when the live source is unavailable. |
| H-LINK-4 independent note | Appropriate default for a newly created free text card and speculative writing. Independence is useful, including when the note resembles an existing scene or character. | “Link existing” and existing promotion/conversion must explain what becomes authoritative and what remains independent. Existing Studio already has typed document/media/canvas references, current document-card projections and transactionally guarded promotion. Preserve and qualify this baseline before claiming a new relationship model. No new character/lore taxonomy or automatic relevance/consistency inference follows from these comparisons.

## Additional source blockers before native acceptance

- **CW-07, P1 — immediate typing before card-insertion acknowledgement.** In the 95a88 source, `add_text` begins asynchronous persistence and `poll` constructs the native editor only after acknowledgement. No input field owns the intervening frames. Immediate native text events can therefore disappear during a slow insertion. The baseline probe explicitly waits for editor mount and does not cover this path. Root accepted this source finding and is implementing retained pending-card input ownership. Add a bounded delayed-insertion/acknowledgement probe: type on the frame immediately after the actual creation click, preserve the same exact card draft through acknowledgement and Save, then verify independent reopen/history. A global keyboard-event capture/replay is not an acceptable substitute for native surface ownership. Source acknowledgement is not a native pass.
- **CW-08, P0 backup integrity prerequisite — asynchronous Save is not backup readiness.** In the 95a88 source, `prepare_workspace_backup` calls `save_explicit` and can continue to the destination/job while board persistence is still pending, or before that write later fails. A consistent database copy taken before the board write can omit current writing. Picker latency is not a durability guarantee. Root accepted the source finding and is adding an exact-board preflight with status, guarded Continue, Review board and Cancel. Continue must recheck acknowledgement and all relevant draft prerequisites immediately before the picker/job. Review retains the same card/draft; Cancel ends only backup. Failed/composing/newer text cannot silently become a verified current-writing backup. Native latency, later-typing, failure and cancellation evidence remains required.
- **Cancellation scope needs explicit review.** Read-only original `CanvasTextCard` source saves on blur/Cmd-Enter and Escape resets the draft to `item.text`. Native periodic acknowledgements can make Cancel discard only the text since the latest acknowledgement. Keep acknowledged revisions intact, explain the actual unsaved scope, and test an acknowledged edit followed by a newer draft and Cancel. The pre-ack cancel bootstrap does not establish this case.
