REQUIRED COMPOSITION

HOM identifiers below are local to this handoff. Map them to the repository's actual specification and scenario IDs during implementation.

HOM-01 Banner
A prominent but bounded top banner: content/action at the left and the expressive medieval scribe at the right on wide layouts. Preserve the hand-on-cheek pose, face and eyes, quill, book stack, manuscript and woodcut linework. The artwork stays fully inside the banner and never covers shared chrome or controls.

HOM-02 Projects
Place the project heading and creation/opening actions below the banner, followed by horizontal project rows. Keep modest thumbnails/icons, readable titles, supported metadata, opening affordances, quiet separators and the demonstrated alignment/rhythm. A dashboard, metrics view or grid of large tiles is not an equivalent implementation.

HOM-03 Integration
Use the current shell and established commands. Preserve the existing first-run and archive-import paths. Avoid duplicated or misleading controls. Project selection and opening must use actual identifiers.

HOM-04 Copy
Reject these strings and translated equivalents:
"Ваши тексты и персонажи рядом"
"Ваши тексты, идеи и персонажи — рядом."

Default to omitting that promotional subtitle rather than inventing a replacement slogan. Show concise functional copy and real project context. The depicted "История ждёт продолжения" is illustrative copy, not a mandatory approved slogan. Empty and unavailable-target states need truthful wording.

HOM-05 Typography
Modern, readable humanist sans-serif in the UI, continuous with WriterCraft. No revival of the rejected serif treatment for the home heading, project names or interface labels. Keep a deliberate hierarchy without oversized/heavy headings. Scope styling locally; preserve the manuscript's independent typography.

HOM-06 Theme adaptation
Use existing semantic theme tokens and retain all seven palettes plus independent Light/Dark/System behavior. Adapt the scribe's clothing and decorative field to the palette while retaining neutral skin/paper/linework. Use intentional masks/layers or prepared variants; do not rely on indiscriminate full-image tinting. Do not recolor actual user-owned thumbnails/content. The small approved logo in the existing shared shell remains unchanged.

HOM-07 Real state
Only display "Continue" if a valid existing target is known. Do not fabricate a chapter/caret restoration ability, statistics, timestamps or save success. Preserve existing unavailable-target/error handling. Decorative project thumbnails must not require a new cover-editing workflow.

RESPONSIVE BEHAVIOR

HOM-08 Available content width
Measure the width left for the home body after existing panes/chrome. Do not compute layout solely from the outer window width.

Wide: side-by-side banner text/action and scribe; aligned banner/list edges; bounded readable text.
Constrained: reduce decorative gaps and illustration size, wrap labels/actions, retain useful hit targets.
Narrow: stack banner regions where necessary; keep action and text prominent, preserve the character's meaningful silhouette. Project rows retain title/opening access while secondary metadata wraps or yields space.

Do not shrink the entire screenshot, clip controls, overlap text, crop the face/quill/book, or introduce horizontal scrolling for ordinary home content. Short windows require a smaller banner and usable local vertical scrolling so the project list stays reachable. Respect the existing shell's scrolling behavior.

Use content-driven breakpoints. No exact breakpoint numbers were owner-approved.
