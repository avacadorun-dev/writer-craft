## Source findings requiring ordinary implementation

These are source findings, not newly invented owner reports or reproduced native failures. They belong to the existing #9 correction.

1. **A3-UX-01, P2 — error dialog action bypasses the shared rhythm.** `app/dialogs.rs`, the `Attention needed` modal, uses `ui.button("Understood")` directly without the shared footer/action helper. It can therefore fall back to the shallow default action that the owner rejected. Use the existing shared action row rather than enlarging only the surrounding frame. Verify the error body and technical-details expansion leave the action reachable at the smallest supported window.
2. **A3-UX-02, P2 — image chooser action bypasses shared sizing.** `app/authoring.rs`, the Image properties dialog, uses `ui.button("Choose image…")` directly, whereas the fields and Insert/Cancel use the 40-point shared metrics. Give the chooser the same intended form-action target. Keep cancellation semantics: cancelling a second chooser must retain a previously selected pending image.

The code-language ComboBox, source Copy icon and modal close target are compact utility controls with a different role. Their actual target, label, focus and keyboard behavior must be reviewed, but a blanket demand that every utility be a 40-point primary button would unnecessarily crowd the approved workspace.

## Design conditions for upcoming integrations

### Tables

The user's capacity exception is 63 logical columns, including spans. Reject unsupported growth before mutation and explain wider imported tables as preserved read-only content. Ordinary authoring remains in the native document, with contextual operations close to the selected table and labeled overflow when space is limited. Do not bolt a separate spreadsheet window onto the manuscript or replace existing source controls with a raw JSON inspector.

The selection must remain understandable when toolbar/menu focus moves: distinguish text/caret, cell range and selected table. Keyboard and pointer operations act on the same captured target; Escape exits the innermost mode. Contextual structure changes, Copy/Cut/Paste, marks, Undo/Redo and save/reopen must retain exact surrounding content and metadata. Engine tests qualify engine contracts; the actual consumer must still prove its mounting, input and persistence integration.

### Portable export and restore

Keep local data location, whole-workspace backup, Markdown reader export and canonical project restore distinct in ordinary language. The user should see what is included and where it goes, without internal framing/schema names in the primary flow. Markdown is a useful readable interchange, not a lossless replacement for notes, histories, Canvas and source relationships.

Use the existing native destination picker and shared modal/grid. An import/restore preview must summarize the actual recognized project and unresolved limits before an explicit action; a parser preview is not an import success. New-project identity/collision handling must preserve the independent source. A failed/cancelled operation never says success or leaves an unexplained partial project; show a persistent actionable outcome without overwriting unrelated files.

### Rich assistant review

Preserve the source-backed authority model: selection alone sends nothing. An explicit selection attachment shows document, exact quote/scope and base revision; later navigation cannot retarget it. Rich proposals remain noncanonical until Apply. Show a readable changed excerpt with context and old/new emphasis, preferably in the existing inspector for a local change; only larger multi-document work needs the central review surface.

Display stale state before Apply when possible; keep the suggestion readable and offer an explicit route forward. Apply/Reject/guarded Undo remain adjacent and understandable. Never present a local scripted replacement as model output. Source/backend coverage cannot substitute for a native attachment→preview→Apply/Reject→stale/Undo journey.
