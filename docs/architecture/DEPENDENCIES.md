# Dependency decisions

The first MVP is a Rust workspace with a small independent domain/persistence core and native egui desktop. It has no WebView, Electron, browser runtime, Docker, PostgreSQL or object-storage server requirement. This document describes selected roles, not completed product parity. Exact resolved versions and transitive dependencies are recorded in `Cargo.lock`.

| Dependency | Role and constraint |
| --- | --- |
| eframe / egui `=0.36.2` | Native desktop renderer/input/accessibility. Use published matching versions; do not silently mix the Artcraft egui fork. A basic TextEdit edits native MVP prose; it is not a replacement rich-document engine. |
| rusqlite `0.37`, `bundled` | Local transactional SQLite; bundled SQLite removes the user's server/package installation step. Persist canonical revisions and reviewed proposals in the same core. |
| serde / serde_json `1` | Typed wire data plus opaque `Value` retention for unsupported imported rich data. Unknown source fields are retained; text preview is never canonical rich data. |
| thiserror `2` | Typed actionable library/domain errors. |
| uuid `1` | Native IDs; imported IDs remain provenance and require mapping. |
| sha2 `0.10` | SHA-256 attachment integrity and core fingerprints. |
| zip `3`, default features off, `deflate` | Bounded read-only `.wstudio` archive inspection; no generic extraction. CRC plus declared SHA-256 are checked. |
| rfd `=0.17.2` | Native file dialogs. Keep domain I/O and mutation policy outside the dialog adapter. |
| image `0.25`, PNG only | Screenshot/verification artifacts and narrowly scoped image functionality; not a promise of complete media import decoding. |
| tempfile `3` (test dependency) | Isolated persistence/archive acceptance fixtures. |

Rust application code is compiled to native binaries. Native rendering still depends on operating-system graphics and window infrastructure. Offline prose editing is independent of online AI; connecting a remote model later will require explicit provider configuration and may incur provider charges. No script or template output should be labeled as generated by an AI provider.

## Current transfer boundary

`studio-transfer::inspect_archive` reads a `.wstudio` ZIP without creating/extracting files or importing a project. It enforces compressed and expanded total limits of 512 MiB, a 64 MiB manifest limit, and at most 40,002 entries. A bounded central-directory pass rejects duplicates before the ZIP library builds its name index; ZIP64 and multi-disk directories are deliberately unsupported. It rejects unsafe/non-portable paths, non-regular Unix entry types, case-colliding/duplicate entry names, undeclared entries, unsupported envelope versions, mismatched attachment sizes/hashes and inconsistent current document revisions.

The result retains the entire manifest and each current rich JSON document, alongside the exported plain-text preview. It intentionally does not claim complete project-domain, image/PDF decoder, annotation-anchor, Canvas-link or editor-schema validation. The original archive remains the authoritative complete asset container. A preview is never an editable migration. Preserve the archive and its provenance before introducing an import that persists selected documents.

The first supported envelope range is 1–8 (`writers-studio-project`). Document schema versions are separate. Semantic Markdown-tree migration, actual rich-text editing, binary extraction/asset storage, dictation audio capture, transcription, Canvas interaction and full exports require their own tests and implementation.

## Candidate dependencies deliberately deferred

See [Artcraft research](../research/ARTCRAFT.md). WordCraft's document/engine modules are promising but bring significant rendering/formats/proofing dependencies; FigCraft and DeckCraft engines carry application-specific models. `craft-ui` currently targets egui 0.37 and an upstream suite with a patched egui family. None is incorporated merely to reuse a screenshot or imitate a UI.

`craft-atomic` is a strong future candidate for safe project/asset files. Today SQLite transactions protect local database state; no untested promise is made about power-loss survival, network filesystems, installer signing, auto-updates or three-platform release readiness. Distribution work must verify those independently.

## Engineering discipline

Follow the installed repo Rust skill and `AGENTS.md`: typed errors, no production unwrap/expect, relevant tests, `cargo fmt`, `cargo test`, and `cargo clippy --all-targets --all-features --locked -- -D warnings`. Keep `Cargo.lock` under version control. New Git dependencies require an immutable revision, license/provenance review and a verified need. Avoid introducing a second core mutation path through UI, CLI or an eventual MCP adapter.
