# ADR-DIST-001: Native engineering installer qualification

Decision date: 2026-11-08. Status: implementation selected; hosted and owner acceptance pending. Tracking: [issue #3](https://github.com/avacadorun-dev/writer-craft/issues/3). The owner's expanded alpha.2 instruction supersedes the earlier installation deferral. It does not authorize alpha.2 publication.

Use OS packaging tools rather than another application framework: Apple's `hdiutil` creates an HFS+/UDZO DMG; NSIS 3.12 creates a per-user Windows installer; `dpkg-shlibdeps` and `dpkg-deb` create an amd64 Debian package. App code and Cargo manifests remain outside this change. A read-only-permission Actions workflow, dispatched manually or triggered by installer-owned changes on the approved integration branch, freezes one commit, builds on hosted machines and combines artifacts only after every platform check passes. Existing release/preview workflows and immutable alpha.1 assets are untouched.

NSIS was selected instead of WiX 6 after inspecting their primary licensing policies: WiX introduces maintenance-fee conditions, while NSIS's core/System plugin and zlib compressor use the permissive zlib/libpng license with no user fee. The workflow downloads the unmodified official [NSIS 3.12 ZIP](https://sourceforge.net/projects/nsis/files/NSIS%203/3.12/nsis-3.12.zip/) and checks SHA-256 `56581f90db321581c5381193d796fffcf2d24b2f8fed2160a6c6a3baa67f2c4f`, computed from that official artifact on 2026-11-08. The archive's `COPYING` is shipped. `SetCompressor zlib` avoids using the separately licensed LZMA compression module. No additional plugin, .NET runtime, signing credential or system-wide compiler installation is required. NSIS's own [COM helpers](https://github.com/kichik/nsis/blob/master/Include/Win/COM.nsh) and [property keys](https://github.com/kichik/nsis/blob/master/Include/Win/Propkey.nsh) set the Start menu identity through Windows `IPropertyStore`.

Windows builds explicitly use `-C target-feature=+crt-static`; bounded PE normal/delay import inspection rejects Visual C++ redistributable DLL dependencies that a development runner could otherwise hide. This keeps the per-user installation independent of a machine-wide redistributable installer. The check follows the [Rust CRT linkage contract](https://doc.rust-lang.org/reference/linkage.html#static-and-dynamic-c-runtimes) and [Microsoft PE import format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format). Windows program files live under LocalAppData/Programs, separate from the application's roaming AppData workspace. Generated installation commands enumerate files; uninstall deletes exactly those files and uses only nonrecursive empty-directory removal. It does not enumerate, clean or remove the user-data directory. Hosted verification checks a binary user-data sentinel and an unknown program-directory file before/after installation and uninstall, as well as installed notices, source metadata, executable checksum/version, registry identity and shortcut application ID. Full SemVer is retained in DisplayVersion, PE string metadata and installed JSON; numeric PE resource version encodes prerelease phase/sequence in the fourth field (alpha 1–299, beta 301–599, rc 601–899, final 999). This is separate from the application version and never rewrites Cargo metadata.

Linux builds against a pinned official `rust:1.97.0-bookworm` container image (`sha256:8fa55b2f3ddf97471ab6a767bfa3f37e6bad0986ba823e75fea57e2a2a5c3073`) on the hosted amd64 runner. The digest and Rust version were resolved from the official registry on 2026-11-08. Debian 12/glibc 2.36 is the build baseline; Debian 12 and Ubuntu 24.04 install the **same** `.deb`, compare its binary and metadata, run `--version` without opening the GUI, validate the desktop entry, check `ldd`, remove and purge while retaining their own real user-data sentinel. Container use is a CI implementation detail, never an installation prerequisite. The package has no maintainer scripts or user-data paths. Debian prereleases replace `-` with `~` so alpha versions sort before the corresponding final version.

The macOS bundle uses the normal application identity, contains generated feature-matching notices and retains the original icon. The packager verifies its thin ARM64 binary/version/commit before and after copying onto the DMG; mounts read-only; checks the HFS+ filesystem and exact `/Applications` symlink; verifies the packaged ad-hoc signature; and executes only `--version`. It never opens, restarts or replaces the owner's running preview. Ad-hoc signing provides bundle consistency, not Developer ID or notarization.

Every package has an executable hash and package hash, full source fingerprint, target, feature list, source commit and version. The collection step rejects missing/duplicate platforms, mismatched versions/commits/fingerprints, modified packages/checksum files, missing installation checks and unsupported release/UX claims. No private source workspace, archive, manuscript or personal file is an input. Fixture tests exercise these refusal paths and the uninstall ownership boundary without builds or installation. Native compilation/installation results must come from the actual hosted run; source tests cannot substitute for them.

Primary packaging references: [Apple disk-image packaging](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution), [NSIS license](https://nsis.sourceforge.io/License), [NSIS System plugin](https://nsis.sourceforge.io/Docs/System/System.html), [Debian dependency policy](https://www.debian.org/doc/debian-policy/ch-sharedlibs.html#generating-dependencies-on-shared-libraries), and [dpkg-shlibdeps](https://manpages.debian.org/bookworm/dpkg-dev/dpkg-shlibdeps.1.en.html). Tool versions and action commits are explicit; update them deliberately and repeat qualification.
