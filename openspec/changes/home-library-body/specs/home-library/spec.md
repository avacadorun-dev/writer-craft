## ADDED Requirements

### Requirement: Selected home body
The home library SHALL use native text and controls to present the selected bounded medieval-scribe banner above horizontal project rows inside the established application shell.

#### Scenario: Wide library
- **WHEN** a library has sufficient available body width
- **THEN** the banner places action and actual context at the left and contained scribe artwork at the right, followed by project-section actions and readable horizontal rows.

#### Scenario: Empty library
- **WHEN** no project is available
- **THEN** creation, archive import and the existing sample path remain reachable without invented continuation context or statistics.

### Requirement: Truthful project actions
The library MUST reuse actual project identities and established commands. Continue SHALL appear only for an available target. Unsupported metadata and the rejected promotional subtitle SHALL be absent.

#### Scenario: Valid continuation
- **WHEN** the currently loaded project is still in the library
- **THEN** Continue opens that exact project through the existing guarded operation, without claiming unsupported caret restoration.

#### Scenario: Missing continuation
- **WHEN** there is no valid current project target
- **THEN** the library offers truthful creation/opening actions rather than guessing a recent project.

#### Scenario: Duplicate titles
- **WHEN** projects share a title
- **THEN** opening operates on the activated row identity, preserving all other project content.

### Requirement: Responsive available body
The library SHALL reflow using available body width and height, preserve readable type and reachable controls, and scroll locally without horizontal overflow.

#### Scenario: Constrained and short window
- **WHEN** available width or height decreases or the window resizes live
- **THEN** banner regions and actions wrap or stack, illustration proportions remain intact, and the project list stays reachable.

#### Scenario: Existing shell offsets
- **WHEN** the shared header, footer and resized navigator allocate space before the central body
- **THEN** centered content width is clamped to the remaining body and every banner, row and action stays inside its bounds, including its nonzero origin.

#### Scenario: Selected body fidelity
- **WHEN** the wide native body is compared with the selected blue-Light or copper-Dark reference
- **THEN** it preserves banner insets and hierarchy, a substantial contained right-hand scribe and subtle print field, and project actions aligned at the trailing edge.

#### Scenario: Long localized content
- **WHEN** long project titles or any of the eight interface locales are displayed
- **THEN** controls remain inside the body, complete titles remain discoverable and keyboard focus can reach every action.

### Requirement: Theme and content isolation
The home body SHALL retain seven palettes and independent Light, Dark and System modes, using semantic theme colors and established sans-serif UI typography. Artwork adaptation MUST preserve neutral paper/skin/ink and user content.

#### Scenario: Palette changes
- **WHEN** appearance or palette changes
- **THEN** the home artwork and body harmonize with it while shared branding, manuscript typography, original user images and project records remain unchanged.

#### Scenario: Independent acceptance
- **WHEN** issue #18 is proposed for completion
- **THEN** exact-candidate hosted checks, actual compiled home captures and interactions, and independent scoped review substantiate its whole acceptance matrix.
