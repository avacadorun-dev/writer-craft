# Research meaningful writing workflows before selecting project profiles

## Why

The existing seven Studio project kinds were introduced without validated workflow hypotheses and some distinctions remain nominal. Direct object sizing and useful professional formatting also require evidence from real screenwriter/editor/writer tasks. Issue #14 selects this discovery and explicit user-scenario documentation, while old Studio import compatibility remains mandatory.

## What changes

Audit existing kinds; compare STARC, Final Draft, WriterDuet/WriterSolo separately, Fade In, Celtx, Scrivener, Obsidian, FocusWriter, Google Docs and relevant Word formatting. Record primary/user evidence and contrary findings. Separate hypotheses for project profiles, starting templates, document editing modes and publication profiles. Maintain stable-ID user scenarios and trace each selected capability to specifications, implementation and actual native acceptance.

Research coherent board/document and character/lore/knowledge relationships as explicitly requested in #14. Compare canonical views, live references, pinned snapshots and independent notes; record editing, synchronization, return navigation and lifecycle semantics before selecting an implementation.

## Impact

This change establishes a discovery/decision contract. It does not select every competitor feature, implement a nominal selector, remove old kinds or claim professional workflow parity. Existing alpha.3 editor/import/portability work continues against its approved source-backed requirements. Generic mechanics remain external engines; profile/domain policy remains in WriterCraft.
