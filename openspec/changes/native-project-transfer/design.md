# Native transfer state and return design

Use one `project_transfer` state with explicit configure/check/ready/prerequisite/worker/outcome
views. Only one checked input/job is retained per window. Dedicated workers own actual database
connections. A restore preview owns the already verified private disk index; confirmation never
reopens the source path. Preview counts identify preserved current items, boards and artifacts,
not native-delta history totals or completed editable capability.

Save current writing and await the shared Canvas acknowledgement helper. Filter pending note IDs
against actual documents owned by the target project. Review pauses the transfer and opens the
existing note view; it never commits other-project notes. A shared `navigation_return` bookmark
stores project/object IDs, saved revision, borrowed-content SHA256, typed selection and measured
scroll/camera only. It stores no manuscript clone, renderer/media cache, sealed replay receipt or
session-bound selection bookmark. A return reopens current data, checks identity, then applies
validated public selection/presentation methods; stale sources remain fresh and are disclosed.

Native destination pickers choose an absent archive path or a parent plus one validated portable
folder name. Result state stays available from File/settings after modal dismissal. Completed
publication wins over later Cancel; missing acknowledgement is actionable and not invented success
or false rollback. Original Studio import and workspace backup continue their own UI. Selected
format2 source closure/privacy remains open. Actual native keyboard/minimum-window/localized,
failure/cancel/collision/restore-reference journeys and independent review remain mandatory.
