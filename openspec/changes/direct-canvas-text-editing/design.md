# Direct card input, persistence and history

The separate generic CraftCanvas text editor owns one exact session/node/source draft and a private stable egui widget ID. The host mounts its actual TextEdit inside the reserved/clipped card at the current zoom; there is no floating input over another card. Local scroll, native Unicode selection, clipboard, local Undo and composition own child input instead of dragging/deleting cards. The original primary dialog is removed. Done/Cancel remain discoverable in the board toolbar. Existing source Markdown is exact; no rich-body conversion is implied.

A new-card command creates one provisional editor and arms its input ownership during activation while durable insertion proceeds. Focus is granted before the next native input batch; it never waits for durable insertion. An activation intent emitted after painting must not leave an absent TextEdit ID focused in that frame's accessibility tree. Only its exact original record is projected for display; the canonical session remains unchanged. Exact insertion acknowledgement promotes the same editor, preserving its widget identity, selection, composition, local Undo and later text. A double-click on an existing unlocked text card captures the current exact source. OS blur preserves the live draft. Deliberate same-window pointer blur or Cmd/Ctrl-Enter requests finishing. IME preedit/commit frames suppress save/cancel shortcuts and autosave. Escape discards only text not already durably acknowledged. Cancel immediately freezes input and shows an explicit waiting status if a request is in flight; finishing waits for the known outcome. Failure preserves the candidate/draft with retry and preservation actions. Durable insertion/autosaves are not rolled back by Cancel. No text may be accepted after cancellation and silently dropped by a later acknowledgement.

After 600 ms idle outside composition, submit captures the exact current source and prepares against the acknowledged session. A separate worker first writes a full candidate recovery draft using the expected saved head and exact acknowledged draft version, then saves canonically and clears only the matching draft. Only then does the UI Apply the prepared change and acknowledge the exact submitted source. The native input remains available during that worker; later typing is not replaced by its older result, and its TextEdit identity/selection/local Undo remain stable. Subsequent dirty input becomes the next guarded request.

Any failure retains the prepared candidate, exact recovery token and latest native draft. Retry uses that token rather than adopting another observed draft. The current latest text can also be preserved exactly as Markdown; pending board preservation uses the latest valid candidate. Stale bases and another draft cannot be overwritten. Dirty/pending/failed navigation/close is refused; a clean acknowledged in-card editor may leave without losing content. Canonical Undo/Redo operate after editing ends; while the input owns focus, Cmd/Ctrl-Z is local text Undo, including across autosave acknowledgements. Each canonical autosave is an append-only board revision and never rewinds history.

Source/controller tests complement exact-source native journeys: new card→type without dialog, existing card→double-click→Unicode/selection/paste/local Undo, continued typing during slow acknowledgement, composition/OS blur, Done/Cancel, failed/stale save→retry/preserve, restart/recover and board Undo. Inspect compact/wide, Light/Dark and zoom limits with actual compiled captures. No scripted event test or source geometry formula certifies OS IME or native UX.

## Acknowledgement-frame and recovery boundaries

Persistence polling precedes the current UI pass. Therefore a Done acknowledgement may update the retained editor's base but must not finish it there: Text/Paste/IME arriving in that same frame is first consumed by the actual card, then `drive_inline` decides whether the latest committed text is clean. Cancel differs because it already freezes the input; same-batch keyboard Cancel also renders the input read-only before later text events are processed. Composition takes precedence over queued application cancellation.

When a valid `.canvas` candidate cannot be prepared (for example, graph capacity is exceeded), **Preserve full card draft…** provides a separate manual recovery record. `writercraft-card-recovery` version1 stores original board/node/submitted-candidate JSON as strings, exact latest Unicode text, source project/board/revision and an explicitly unacknowledged commit outcome. It has a `.json` extension and is not a valid board, an importable project, or a portable media backup. No source graph is mutated by producing it. Only successful exclusive creation, complete write, flush and sync permits explicit Reload saved board; subsequent native changes invalidate that permission. Existing Markdown preservation and validated `.canvas` preservation remain distinct actions.

The input correction is being qualified on hosted Rust1.95 runners before its application pin changes. Native OS input and independent compiled UX review remain required after these semantic/source checks.

## Native accessibility correction

Real macOS interaction on de161c43 exposed an AccessKit focused-ID invariant failure. CanvasView emits an EditText intent after its body paint; calling a new editor's focus request there can name a widget absent from the completed tree. Activation must bind and arm ownership without requesting post-paint focus. The next matching unblocked pre-input hook transfers only the captured prior focus before egui processes Text/Paste/IME. Ordinary egui focus cleanup then handles an absent/unmounted widget; no synthetic accessibility nodes, disabled adapter or platform-output masking are permitted. The host must reveal and mount the intended active card and report inactive/culled/modal state to the input boundary. A competing new field retains its focus.

Qualification includes real AccessKit consumer processing for activation after paint, next-batch input/composition, and an unmounted input, followed by actual macOS activation/clipboard testing. A scripted headless tree test is complementary evidence, not OS input acceptance.
