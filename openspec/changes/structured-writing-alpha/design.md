# Hierarchy-led writing, explicit markup and exact return

The original free schema already allows nested folders, documents and notes. Use this source-compatible structure for native organization without adding project kinds. Imported novel/screenplay/custom schemas retain their exact labels/rules. Domain commands own validation, stable aliases, transactions and optimistic guards; the navigator only presents choices. Native initialization must preserve existing flat documents and avoid rewriting imported raw manifests.

Select containers independently of disclosure state. Offer root/child creation, rename, move/reorder, trash and restore from localized context/keyboard-accessible controls. Trash is recoverable and distinct from permanent purge; preserve descendants and references. A stale target/schema or invalid parent fails before mutation. Tree presentation never silently changes manuscript text. Creation and moving use current saved allowedChildren/canBeRoot/contentBearing rules.

Reference consultation uses existing NavigationReturn: save and acknowledge the current scene, capture exact revision/selection/measured scroll/panes, open the chosen document and retain the bookmark until successful return. Do not infer links from names. A changed origin opens latest content with an explicit changed-context message instead of stale caret application. Return does not claim preservation of an in-memory editor undo stack across reopened sessions.

Extend passage-note metadata with author-defined tags under an additive compatible representation. Retain exact Unicode-scalar anchors and existing mapping/detachment/history authority. Empty tags preserve old records. Tag changes cannot retarget a note or rewrite prose. Project results are scoped by project ID and reference exact document/note IDs; duplicate words/names are not identity. Tags are manual labels, not fixed entity types or provider inference. Canonical import/export must retain metadata/history; reader inclusion follows explicit privacy scope.

Workspace schema 10 is a metadata-only opener boundary: older binaries must refuse this database instead of erasing tag fields on write. Opening an older database does not rewrite annotation/history bytes. Portable format 2 stays additive; old consumers may retain tag extensions as raw evidence but are not certified to edit or rehydrate their semantics. See ADR-016. Clean cached markup drafts adopt refreshed canonical fields; unsaved author drafts require review before project-wide tag mutation.

F-54 advances the current opener boundary to schema 11 and adds a separate guarded label catalog as described in ADR-017. This preserves the initial schema-10 tag contract while protecting colors/shared definitions from older tag-only writers. The migration does not rewrite annotation/history JSON or the original source manifest.

Native validation is a complete author session in The Last Light, created and edited through the actual UI. Shared commands/tests corroborate persistence and refusal paths but do not substitute for interaction. Independent review covers the same active issue and exact source; all release claims remain scoped.

F-54 removes persistent per-item Add/More buttons. The entire tree title row remains the selection/drag target; right-click and Shift+F10 expose the same schema-aware actions. Shared root/project controls remain in the header. This supersedes adjacent-button presentation without reducing drag, keyboard or lifecycle behavior.

F-54 also selects reusable project label names and colors. Keep color definitions separate from manuscript/annotation anchor authority. Existing exact tag spelling stays compatible; color is presentation metadata, not an inferred entity class. The first assigned label supplies the primary inline color, and every assigned label remains a named chip in explicit order. Use a small named palette with appropriate Light/Dark values. Inspector lists size to their content up to a bounded maximum; details immediately follow, with labels, quote and note visually distinct. Source/API design and durable migration must be reviewed before qualifying this correction.

F-55 exposes direct removal on each mark and beside the selected detail, without a confirmation modal for recoverable local deletion. A nearby Undo restores the exact deleted identity under revision/catalog guards; Project markup remains the durable recovery route for older removals. Removing a mark with an authored draft atomically retains that draft in its recoverable tombstone, instead of discarding it or saving separately before an unguarded delete. Failed/stale operations leave both canonical data and the draft intact. A refresh failure after commit must not make the action retry its mutation.

Local label controls remove an assignment immediately and preserve the project definition and other usages. They use the same guarded draft persistence as note edits. Removing the last label from a note with no body removes the now-purpose-free mark recoverably, retaining its previous definition for Undo. Manuscript text, caret/scroll and exact anchor authority remain separate. The inspector prioritizes source context, editable note, named labels and direct removal; project management and uncommon status/reload operations stay secondary. No new editor/Canvas dependency or database version is needed.

The separate Review tab supports a captured queue of marked identities, including the current Project markup filter. Previous/Next reveal the exact current mark across documents. An unapplied replacement is parked by its captured scope, not discarded or silently recaptured. Apply prepares the existing guarded rich proposal and applies that exact receipt from a single explicit action; preparation remains noncanonical. Apply-and-next advances only after successful application. A failed Apply retains the receipt and wording for a retry without duplicate staging. Closing or pausing retains authored replacement text. Compact excerpts describe actual changed ranges; structural proposals retain a truthful full-preview route. No provider or automatic editing is implied.
