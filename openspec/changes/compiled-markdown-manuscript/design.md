# Compiled Markdown manuscript design

Reuse `studio-transfer`'s `MarkdownRenderer` as the only rich-to-Markdown mapping. Add two bounded renderer inputs: `heading_offset` (shift authored headings beneath a chapter heading, capped at level six) and `anchors` (map an included document identity to a stable in-document anchor instead of a sibling file link). Folder export passes zero/empty values; its behavior is unchanged.

A new `compiled_markdown` module owns the plan and the single-document output. The plan resolves `ManuscriptSelection` (current document, subtree, explicit documents) against the captured `ProjectExportSnapshot` manifest using the existing tree-order rule (`position`, then array order). Every included folder emits a section heading; every included document emits a chapter heading with an `id="document-<node>"` anchor, then its current revision rendered with the heading offset. Selections never include drafts, notes, annotations, revisions, research, credentials or machine paths.

Referenced media are collected from the included current revisions only. Missing snapshot artifacts refuse the export before any file is created. Assets are copied from `ProjectExportSnapshot::assets()` into `<stem>-assets/` with deterministic, collision-safe portable names (Unicode-stripped base plus identity digest) and linked relatively from the one `.md`; original bytes and SHA-256 are verified by reading back.

Destination handling follows the existing completion-marker protocol instead of claiming universal atomic replacement: the destination must be a new directory, files are created exclusively, a `.incomplete` marker is written first, every payload is verified and synced, and the marker is removed only after complete success. Cancellation is checked before creation and between payloads. No recursive deletion touches user paths.

The native flow lives in the existing project-transfer modal as a bounded export mode with scope selection, an order preview and a pre-export disclosure list. It uses a dedicated worker and the shared cancellation token; visible text goes through the eight catalogs. No new dependency or persistence decision is required; ADR coverage is not needed because this reuses accepted transfer/revision-snapshot semantics.

Verification maps ME-01..ME-06 to focused `studio-transfer` tests (order, selection exclusion, anchors, assets, collision safety, cancellation, incomplete output), the existing renderer tests, a native compiled observation by the owner, and an independent scoped review. Markdown is not advertised as lossless; structured-writing and full-parity gates stay pending.
