# Source-backed structure commands

The original `internal/store/documents.go::CreateDocumentNode` reads the current structure under a transaction, validates the parent and type placement, appends sibling position, and creates revision1 only for content-bearing kinds. Preserve those distinctions. `project_nodes` already holds current logical metadata separately from the immutable original manifest/source records. Existing contentless aliases reserve a project-scoped native identity, allowing first content to retain the same logical target.

Read the preserved project's structure revision and unknown schema fields without inventing new defaults for imported projects. Every mutation re-reads it under an immediate write transaction. Creating a node checks the expected structure revision, allowed root/child kind, active in-project parent, source depth/count/position bounds and title before inserting anything. First-content initialization checks the exact captured node metadata/ordinal/native binding and current content-bearing kind; stale/repeated/trashed/contentless requests fail unchanged.

A new content-bearing node gets one empty canonical model document and matching plain/rich revision1. A structural node gets its stable node/document aliases without a text handle. First-content initialization reuses the reserved alias, refusing inconsistent or occupied bindings. Keep native handles distinct from source logical IDs. Store current metadata in project_nodes, retain all unknown existing fields and preserve original source bytes. The existing canonical export/restore protocol must retain new heads and nodes while the old source baseline remains immutable.

No schema migration or dependency is needed. Domain policy remains in WriterCraft core; GUI and future authorized headless/MCP adapters call the same guarded commands. UI controls must be designed against the saved schema and normal Cancel/save/recovery prerequisites before exposure; a future-profile selector is not part of this change.
