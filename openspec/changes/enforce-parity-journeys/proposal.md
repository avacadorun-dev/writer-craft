# Enforce source completeness and complete writing journeys

## Why

F-45 identifies a false acceptance risk: the native board can look polished while omitting much of the original workflow. Existing release validation checks a named UX scope and screenshots, but its separate parity requirement begins only at1.0. Alpha.3 already requires complete selected source-backed migration and coherent task flows.

## What changes

Extend the existing UX gate with required inventory, capability and role-journey evidence. Keep one acceptance authority. Require reviewed source inventories, reachable native operations, semantic/native records and complete task paths for both parity scopes regardless of major version. Bind requirements and reports to exact source/lock identity. Keep ordinary source checks usable while implementation is pending.

## Impact

Governance/tooling only: no runtime or persisted manuscript change, no new native acceptance claim, no new generic dependency. #17 explicitly records original Canvas authoring; #14 keeps researched additions separate. Existing alpha.2 tags and historical acceptance stay unchanged. One active product implementation remains #15.
